## How to use

Этот чеклист проводит вас по ручной проверке шести сценариев. Всё остальное уже проверено автоматически (726 проверок) — сюда попало только то, что невозможно проверить машиной: живой диалог с ассистентом и работа в настоящей пользовательской среде.

1. Прочитайте весь чеклист до начала работы, чтобы понимать, что вас ждёт.
2. Выполните общую подготовку (ниже) — без неё ни один тест не пройдёт.
3. Выполняйте шаги по порядку. После каждого сверьте фактическое поведение с колонкой «Expected Result» и запишите, что произошло на самом деле, в колонку «Result».
4. Ставьте `[x]`, если шаг отработал как ожидалось, и оставляйте `[ ]`, если что-то пошло не так.
5. В строке «Notes» внизу каждого теста записывайте всё необычное — даже если тест в целом прошёл.
6. Закончив, верните документ разработчику.

## Общая подготовка (обязательно, один раз)

**Что здесь проверяется, в двух словах.** Есть команда, которая приводит любой проект к актуальной версии рабочего процесса — неважно, начинали вы с пустого каталога, со старой версии или с наполовину обновлённой. И есть ассистент, который подсказывает следующий шаг работы над задачей. Раньше ассистент считал шаг выполненным просто потому, что нужный файл существует — даже если внутри файла была одна строчка-заглушка. Из-за этого он мог отправить вас писать код по плану, которого на самом деле нет. Вы проверяете, что это больше не случается.

**Шаг 0 — сделайте резервную копию.** Тесты 5 и 6 работают с вашей настоящей пользовательской папкой, а не с временной. Перед началом:

```bash
cp -r ~/.claude/skills ~/.claude/skills.backup-$(date +%F)
cp ~/.claude/bin/pf   ~/.claude/bin/pf.backup-$(date +%F)
```

Если что-то сломается — вернёте из копии. **Не пропускайте этот шаг.**

**Шаг 1 — установите свежие подсказки ассистента:**

```bash
cd <каталог проекта planning-framework>
bash scripts/update-skills.sh
```

Без этого ассистент будет работать по старым правилам и все тесты покажут старое (неверное) поведение.

**Шаг 2 — подготовьте два тестовых проекта.** Возьмите две заготовки и приведите каждую к актуальной версии:

```bash
cp -r test/fixtures/v2-project      /tmp/proj-A
cp -r test/fixtures/v2-with-stub    /tmp/proj-B
make converge TARGET=/tmp/proj-A
make converge TARGET=/tmp/proj-B
```

Разница между ними: в проекте **B** лежит файл-заглушка — документ, у которого вместо содержания одна строчка «здесь надо будет всё написать». Именно на нём ассистент раньше и ошибался.

## TC-046: Файл-заглушка не считается готовым документом

**Prerequisites:**
- Открыта сессия Claude Code **в каталоге `/tmp/proj-B`** (тот, где лежит заглушка)
- На вопрос про размер отвечайте **`medium`**

**Steps:**

| Step | Action | Expected Result | Result |
|------|--------|-----------------|--------|
| 1 | Введите `/pf` | В «Completed stages» **нет** строки `TEST_PLAN` — ассистент распознал файл как заглушку, а не как готовый документ | [ ] |
| 2 | Проверьте, есть ли `IMPL_PLAN` | Тоже нет: предыдущий этап не завершён, значит и следующий не может считаться завершённым | [ ] |
| 3 | Прочитайте «Next step» | Предложен самый первый незавершённый этап цепочки, а не тот, что «после» заглушки | [ ] |
| 4 | Создайте файл `qa_report.md` из одного заголовка (`# QA`) и снова введите `/pf` | Этап `QA` **не** засчитан: правило «пустой файл ≠ готовый документ» работает для всех типов документов, а не только для плана проверок | [ ] |
| 5 | Загляните в папку `docs/issues/closed/` | Там есть файл `brd.md` со ссылками на старые документы. На подсказки ассистента он **не влияет** — закрытые задачи не участвуют в маршруте | [ ] |

**Notes:** Это ровно тот сбой, что наблюдался на реальном проекте: ассистент рапортовал «сделано: CREATE, TEST_PLAN, IMPL_PLAN» и предлагал запускать работу — против документа, в котором была одна строчка-заглушка.

## TC-047: Самый опасный сценарий — ответ «маленькая задача»

**Prerequisites:**
- Свежая копия: `rm -rf /tmp/proj-C && cp -r test/fixtures/v2-with-stub /tmp/proj-C && make converge TARGET=/tmp/proj-C`
- Открыта сессия Claude Code **в каталоге `/tmp/proj-C`**
- На вопрос про размер отвечайте **`trivial`** (маленькая задача) — в этом вся суть теста

**Steps:**

| Step | Action | Expected Result | Result |
|------|--------|-----------------|--------|
| 1 | Введите `/pf` и ответьте `trivial` | Ассистент принял ответ и работает по короткой схеме для маленьких задач | [ ] |
| 2 | Прочитайте «Next step» | Предложено `/pf-brd` — сначала описать задачу | [ ] |
| 3 | Выполните `/pf-brd` | Создан файл `notes.md` | [ ] |
| 4 | Введите `/pf` ещё раз | **Ключевой шаг.** Предложено `/pf-test-plan` — и **НЕ** предложено `/pf-execute`. Хотя оба файла формально «есть», один из них заглушка | [ ] |
| 5 | Проверьте, что запуск работы не был предложен ни разу за все шаги | Не был | [ ] |
| 6 | Выполните `/pf-test-plan`. Ассистент заметит существующий файл и предложит выбор — выберите «перегенерировать». Затем снова `/pf` | Только теперь маршрут доходит до запуска работы | [ ] |

**Notes:** Короткая схема для маленьких задач смотрит на наличие файлов напрямую — из-за этого именно она и была самой уязвимой. Если на шаге 4 предложено `/pf-execute` — это провал теста, и его надо описать подробно.

## TC-048: Существующий файл не блокирует работу насмерть

**Prerequisites:**
- Любой из подготовленных проектов, где уже есть файл плана работ
- Открыта сессия Claude Code в нём

**Steps:**

| Step | Action | Expected Result | Result |
|------|--------|-----------------|--------|
| 1 | Введите `/pf-impl-plan` при уже существующем файле плана | Ассистент **не** останавливается с отказом, а предлагает выбор: перегенерировать / оставить / отменить | [ ] |
| 2 | Выберите «оставить» | Файл не изменился, ошибки нет | [ ] |
| 3 | Повторите и выберите «перегенерировать» | Файл перезаписан заново | [ ] |
| 4 | Повторите и выберите «отменить» | Файл не изменился, показано сообщение об отмене | [ ] |
| 5 | Проделайте то же для `/pf-test-plan`, `/pf-brd`, `/pf-spec` | Везде тот же выбор из трёх вариантов | [ ] |
| 6 | Удалите план проверок и введите `/pf-impl-plan` | Здесь ассистент **обязан** отказаться: нельзя строить план работ без плана проверок | [ ] |
| 7 | Удалите план работ и введите `/pf-execute` | Тоже отказ | [ ] |

**Notes:** Шаги 1-5 проверяют, что тупика больше нет. Шаги 6-7 — что при этом требования не ослабли. Обе половины важны.
