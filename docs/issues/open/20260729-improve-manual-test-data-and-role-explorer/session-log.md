### Решения, принятые автопилотом без пользователя

Пользователь вышел из сессии со словами «работай автономно, вопросов больше не задавай». Далее — всё, что по пайплайну требовало его ответа:

- `[autopilot default]` **/pf-check → «Fix now»** (рекомендованный вариант из трёх). Альтернативы — «исправлю сам» и «пропустить» — требуют присутствия человека либо оставляют P0 неисправленными.
- `[autopilot default]` **P0-1, разрешение противоречия про read-only.** US-05 требовала «всё только для чтения», что запрещало и редактирование чек-листа, и подготовку данных, и уже существующее переключение ветки. Принято: read-only относится к документам пайплайна; изменяющие действия перечислены явно (отметки и заметки в чек-листе, переключение ветки по подтверждению, подготовка кейса).
- `[autopilot default]` **P0-2, место хранения развёрнутых данных.** Требование «данные лежат вне репозитория» заменено на требование по результату — «состояние репозитория с точки зрения VCS не меняется». Это отступление от формулировки в `prompt.md`, где временный каталог вне репозитория был зафиксирован как решение: ревью показало, что как *требование* оно невыполнимо для кейсов, где проверяемый код читает файлы внутри проекта. Временный каталог остаётся выбором по умолчанию на уровне спецификации, с законной альтернативой — gitignored-путь внутри репозитория.

Прочие P1/P2-решения переданы правящему агенту списком и вытекают из уже зафиксированных в `prompt.md` договорённостей.
