# Project Explorer: редизайн навигации, оформления и инбокса дел

Этот документ описывает, что изменилось в Project Explorer (`tools/manual-test-ui`) для пользователя инструмента — тестировщика, разработчика, аналитика — и как пользоваться новыми возможностями.

## Что изменилось

### Двухуровневая навигация вместо сайдбара

Раньше выбор роли, проекта и issue были размазаны по разным частям экрана (вкладки ролей сверху + три независимых списка в сайдбаре сбоку), и у экрана было сразу несколько независимо прокручиваемых областей.

Теперь навигация — два уровня:

- **Лаунчер** (главный экран) — переключатель роли, карточка «Инбокс» со сводным числом всех незакрытых дел, и сетка карточек проектов. Клик по карточке проекта, у которой уже есть последняя активная issue, сразу открывает рабочее пространство этой issue.
- **Рабочее пространство** (уровень 2) — шапка с выпадающими списками `Issue ▾` и `Роль ▾`, под ней — табы документов текущей роли (набор табов у каждой роли свой, соответствует тому, какие документы этой роли видны). Отдельного сайдбара больше нет — вся навигация умещается в одну строку шапки.

Переключение issue внутри одной роли **не** сбрасывает открытый таб документа: если вы читали `test_plan.md` и переключились на другую issue того же проекта, экран остаётся на `test_plan.md` (или показывает, что у новой issue этого документа нет — не перекидывает вас на случайный другой документ). Переключение роли, наоборот, полностью меняет набор табов — документы разных ролей никогда не показываются одновременно.

### Новая цветовая схема

Прежняя схема была на грани нечитаемости (почти чёрный фон, заголовок почти не отличался размером от обычного текста). Новая палитра (Pine) — тёмно-зелёная, проверена на контраст автотестом, подобрана так, чтобы не уставали глаза при долгой работе. Основной текст, статусы (готово/ошибка/предупреждение) и акцентный цвет — все проверенных контрастных пар. Заголовки крупнее тела текста в понятной пропорции.

Каждая смысловая область экрана — отдельная панель с подписанным заголовком акцентного цвета, а не сплошное полотно текста. Таблицы шагов чек-листа используют мягкую тональную заливку чередующихся строк вместо жёстких линий-разделителей.

### Клавиатурная навигация

Все интерактивные элементы (переключатель роли, карточки, выпадающие списки, табы, действия чек-листа) доступны по Tab, и у элемента в фокусе всегда виден чёткий контур — это не зависит от мыши.

### Единый инбокс дел

Новый экран «Инбокс» (доступен с карточки на лаунчере) собирает **все** незакрытые дела пользователя по всем проектам в одном месте, разбитые на два раздела:

- **Ручные тесты** — тест-кейсы со статусом `pending`. Источник этого раздела — общий статус-трекер каждого проекта (`docs/planning/test-plan.md`), а не чек-лист конкретной issue: если вы ищете тест-кейс, который видели в отдельной issue (`manual_test_checklist.md`), но не находите его здесь, — это разные документы, и попадание сюда зависит от того, отражена ли эта issue в общем статус-трекере проекта.
- **Человеческие задачи** — задачи, которые нельзя выполнить автоматически (см. ниже), назначенные вам как исполнителю.

Разделы не смешиваются в одну ленту с одинаковыми карточками — у каждого раздела своя вкладка. У каждого элемента инбокса видно как минимум: проект, issue, что конкретно требуется, и клик по элементу сразу открывает нужный документ/чек-лист/таб «Дела» — с правильной ролью и вкладкой, а не просто «в правильном проекте где-то там». Для ручных тестов клик старается ещё и прокрутить экран к нужному тест-кейсу — это может не сработать, если идентификатор теста в общем статус-трекере не совпадает по формату с идентификатором внутри issue; в этом случае вы всё равно попадёте на правильную issue и таб, просто не будете прокручены к конкретной строке.

Карточка «Инбокс» на лаунчере показывает суммарное число дел по всем проектам сразу, включая явное «0 дел», если очередь пуста.

### Таб «Дела» в рабочем пространстве

У каждой роли в рабочем пространстве появился новый таб «Дела» со счётчиком — сколько у вас незакрытых human-задач **по всем ролям и по всем issue текущего проекта разом**, а не только по той роли/issue, которую вы сейчас смотрите. Это защищает от ситуации «пропустил свою же задачу, потому что смотрел под другой ролью».

Внутри таба — список ваших задач с действиями:

- **Завершить** — для задачи-ревью нужно вписать заключение (текст, любой непустой), для задачи-записи документа/кода — просто подтверждение. Завершение реально проверяется (документ существует, не заглушка, закоммичен; либо у issue-ветки реально есть новые коммиты вне папки issue) — галочку нельзя поставить формально, если работа фактически не сделана.
- **Отдать агенту** — единственное место в интерфейсе, где можно сменить исполнителя задачи (например, передать её от одного агента другому); выбор — из списка настроенных исполнителей проекта.

Незавершённая человеческая задача — это не просто напоминание: пока она не отмечена «Завершить», закрытие её issue (`/pf-close`) не проходит. Если issue не закрывается без видимой причины, в первую очередь стоит проверить таб «Дела» этой issue на всех её ролях.

### Что нового у человеческих задач

Раньше операция, которую нельзя было выполнить автоматически, не имела предсказуемого поведения. Теперь такая операция всегда попадает в очередь (см. таб «Дела» выше) вместо того, чтобы либо зависнуть, либо потребовать ручного вмешательства без единого места, где это видно.

### Проверка чек-листа: пустой результат больше нельзя сохранить как «выполнено»

Раньше шаг ручного теста можно было отметить выполненным, не вписав в него результат. Теперь попытка отметить шаг выполненным с пустым результатом отклоняется — экран покажет понятное сообщение об ошибке вместо того, чтобы молча принять пустую отметку.

### Нераспознанный текст чек-листа теперь виден

Если в файле чек-листа (`manual_test_checklist.md`) между блоками тест-кейсов есть текст, не относящийся ни к одному известному полю, он больше не теряется молча — он показывается в конце экрана чек-листа отдельным блоком «Дополнительные заметки» (визуально отличается пунктирной рамкой), чтобы такой текст было видно и можно было решить, что с ним делать.

**Известное ограничение:** разбор чек-листа сейчас излишне чувствителен — служебные строки внутри блоков «Предусловия»/«Требуемые данные»/таблицы шагов иногда сами попадают в «Дополнительные заметки», хотя относятся к тест-кейсу. На практике блок может показать заметно больше пунктов, чем в файле реально есть посторонний текст. Это существующий, заведённый отдельно баг разбора — не повод игнорировать блок целиком, но и не сигнал, что с чек-листом обязательно что-то не так.

## Что не изменилось

- Способ запуска инструмента — по-прежнему одна команда, без установки дополнительных зависимостей.
- Переключение веток issue по подтверждению и подготовка тестовых данных работают как раньше — и на уровне всей issue, и на уровне отдельного тест-кейса (кнопка с английским текстом вида `Prepare test data for TC-NNN`), просто в новом визуальном оформлении.
- Три состояния документа (отсутствует / есть только на ветке issue / есть на диске) распознаются так же, как раньше.
- Точечная запись результата шага чек-листа по-прежнему меняет ровно одну строку файла, не трогая остальной документ.

## Известные пробелы

- **Поиска по сетке карточек проектов пока нет.** Изначально задумывался, но не был реализован в рамках этого изменения — вынесен в отдельную задачу.
- **Подсветка нужного тест-кейса при переходе из инбокса срабатывает не всегда** — см. оговорку в разделе «Единый инбокс дел» выше.

## Миграция для пользователей

Никаких действий не требуется — при следующем открытии инструмента вы увидите новый лаунчер вместо старого экрана с сайдбаром. Если вы держали открытую вкладку браузера со старым интерфейсом, обновите страницу.

Старый интерфейс не имел закладок на конкретные документы — состояние держалось только в `localStorage`, и URL всегда выглядел одинаково независимо от того, что открыто. Редизайн, наоборот, впервые делает навигацию адресуемой через URL: `#/p/<project>/i/<issue>` (и дальше — параметры роли/таба/тест-кейса при переходе из инбокса) можно скопировать и переслать, чтобы открыть у другого человека сразу нужную issue.
