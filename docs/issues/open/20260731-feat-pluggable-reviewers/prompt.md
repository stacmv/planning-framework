Добавить опциональную поддержку OpenAI Codex (и в перспективе — человека через
внешний API/очередь ревью, по образцу `~/dev/codereview-tool`) в качестве
ревьюера PF-документов (BRD, specs, test_plan, implementation_plan) и кода
реализации, наравне с существующим ревью через Claude.

## Контекст, уже согласованный с пользователем

- **Ревью документов:** происходит там же, где сейчас работает `pf-check`
  (после каждого документа), но с возможностью выбрать ревьюера(ов) для
  каждого документа.
- **Ревью кода:** новый отдельный скилл `/pf-codereview` — новая стадия
  пайплайна между `/pf-execute` и `/pf-test`.
- **Назначение ревьюеров:** на этапе создания issue (CREATE) пользователь
  заранее указывает для каждого артефакта (brd/specs/test_plan/
  implementation_plan/код) — `claude`, `codex`, или оба. Выбор сохраняется в
  issue (нужен новый файл/секция метаданных issue).
- **Механизм вызова codex:**
  1. если установлен глобальный Claude Code плагин `codex`
     (codex:rescue/codex:setup и т.п.) — использовать его;
  2. если плагина нет — предложить пользователю установить; при отказе —
     вызывать `codex exec` напрямую;
  3. если codex в принципе недоступен на машине — молча fallback на claude
     для этого артефакта.
- **Конфликт вердиктов** при двух ревьюерах: замечания обоих просто
  агрегируются и передаются автору документа/кода на рассмотрение и
  исправление — как сейчас делает `pf-check` с одним ревьюером. Никакого
  автоматического арбитража между ревьюерами не нужно.
- **На будущее** (не в scope этой реализации, но абстракция ревьюера должна
  это допускать): третий тип ревьюера — `human`, доставка материалов на
  ревью и приём фидбека через внешний API/очередь (асинхронно), по образцу
  инструмента `~/dev/codereview-tool` (review-queue + боты Pachka/Telegram +
  YouTrack). Сейчас реализовывать не нужно, но дизайн (типы ревьюеров,
  синхронный/асинхронный режим ожидания результата) не должен исключать
  такое расширение впоследствии.
- Сегодня в репозитории planning-framework нет вообще никаких упоминаний
  "codex"/"openai" — это фича с нуля. Единственный существующий механизм
  ревью — `pf-check`, который ревьюит только документы через внутреннего
  Claude sub-agent (Agent tool), не умеет шеллиться во внешние CLI.

Задача взята из недельного плана: "planning-framework: добавить опциональную
поддержку OpenAI codex в качестве ревьюера документов и кода".
