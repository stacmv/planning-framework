## 2026-08-11 — `/pf-check` по урезанной спеке

**Дефект вызова Codex, третий за сессию.** Первый прогон повис на
`Reading additional input from stdin...` и умер по таймауту, не выдав ни строки:
`codex exec` получает промпт аргументом, но всё равно дочитывает stdin, а в
фоновом запуске тот остаётся открытым. Лечится `< /dev/null`. Чейн в `pf-check`
stdin не закрывает — то есть в неинтерактивном контексте может зависнуть молча.
Вместе с пустым диффом и нежизнеспособной песочницей это уже третий независимый
дефект одной интеграции.

**Находки Codex: 5 P1, 1 P2, ни одного P0** — урезанный дизайн держится, но пять
мест были дырявыми. Разобрано и исправлено оркестратором самостоятельно (правки
хирургические, фикс-субагент не дешевле):

1. **Перенос после архивации неисправим.** `/pf-close` ищет активную issue
   только в `docs/issues/open/` (`skills/pf-close/SKILL.md:7`) — сбой после
   `mv` означал бы «No active issue found» и потерю кейсов навсегда. Фаза
   перенесена с 5.5 на **4.5**: после мерджа, до архивации, пока папка на
   месте. Привязки к пути у переноса нет — `Origin` хранит `ISSUE-ID#TC-NNN`,
   а не путь.
2. **Счётчик `Last allocated:` не даёт git-конфликта.** Моё обоснование было
   неверным: две ветки, стартовав с `PTC-0003`, обе запишут `PTC-0004` — для
   git это совпадающее изменение, а не конфликт, и merge пройдёт молча. Модель
   заменена: номер = максимум (счётчик, максимум по таблице) + 1, что
   самовосстанавливается после частичной записи; уникальность между ветками
   больше не *предотвращается*, а *обнаруживается* автотестом с ручной
   перенумерацией. Причина такого выбора записана в спеке явно.
3. **`pf-git` тут ни при чём** — найдено и Codex, и оркестратором независимо.
   Таблицы стейджинга для `/pf-close` не существует: стадия коммитит сама,
   своим `git add` на Phase 8. Правка перенесена туда.
4. **`Medium` против `Med`.** Шаблон issue пишет `Medium`, словарь списка знает
   только `Med`; без нормализации автопроверка падала бы на закрытом словаре.
   Отображение задано явно.
5. **Частичная запись сбивала нумерацию** — закрыто той же моделью «максимум из
   двух».
6. **`Area` (P2)** — эвристика не задавала ни базы диффа, ни того, какие файлы
   считать. Теперь команда указана дословно, `docs/issues/` исключается.
