# Test Plan: 20260818-improve-project-explorer-launcher-search-and-tc-scroll

**Date:** 2026-09-09

## Overview

Issue закрывает два независимых долга Project Explorer (`tools/manual-test-ui`),
отложенных при закрытии `20260806-feat-project-explorer-redesign`: поиск на
сетке карточек проектов (AC-01…AC-06) и прокрутку/подсветку нужного
тест-кейса при переходе из инбокса (AC-07, AC-08).

Обе части устроены по одному и тому же принципу, уже принятому в этом
инструменте для ролевого фильтра (`filterInboxItemsByRoles` в
`public/inbox.js`, `.role-switch`): чистая функция фильтрации/поиска
отдельно от DOM, что делает почти всё поведение проверяемым в
`node --test` под fake DOM без браузера. План отдаёт приоритет Auto:
подстрочный поиск, скрытие разделов, пустое сообщение, отсутствие
персистентности, неизменность выпадающего списка в шапке, a11y-атрибуты,
проброс `tcId` через URL и нахождение нужного `[data-tc-id]` — всё это
факты о данных/DOM, а не о восприятии, и укладывается в существующие
сьюты (`project-picker.test.js`, `launcher.test.js`, `inbox.test.js`,
`workspace.test.js`, `a11y.test.js`). Ручным остаётся только то, что fake
DOM не может дать в принципе — действительно ли подсветка и скролл
воспринимаются человеком в настоящем браузере (AC-07).

**Цели плана:**

1. Доказать все критерии приёмки AC-01…AC-08 из `brd.md`.
2. Отдельно закрыть BR-1 (поиск не переживает перезагрузку, в отличие от
   ролевого фильтра) и BR-3 (нет связи → тихая деградация до перехода на
   вкладку, никогда — подсветка не того кейса).
3. Подтвердить, что AC-05 не регрессирует: `renderProjectSections()` и её
   вызов из `renderProjectSelector()` (шапка других экранов) не получают
   поле поиска — оно только в `renderLauncherProjectSections()`
   (`public/launcher.js`).

## Prerequisites

- Рабочая копия `planning-framework` на ветке issue.
- Node.js той же версии, что требуется для `make test-ui`; `node --test`
  запускается по `tools/manual-test-ui/test/*.test.js` — то же, что
  `make test` уже гоняет для этого инструмента.
- Реализация вводит новую чистую функцию поиска/фильтрации по подстроке
  (по аналогии с `filterInboxItemsByRoles`), вызываемую из
  `renderLauncherProjectSections()` в `public/launcher.js` перед передачей
  данных в `renderProjectSections()` (`public/project-picker.js`) — тесты
  ниже адресуются к этому месту по поведению, а не по гипотетическому
  имени функции, поскольку до реализации issue точное имя не фиксировано.
- Для части про прокрутку: `ptcId` (формат `PTC-NNNN`, из
  `docs/planning/test-plan.md`, `collectManualTests()` в `lib/inbox.js`) и
  issue-локальный `tcId` (формат `TC-NNN`, из `manual_test_checklist.md`
  issue, `parseChecklist()` в `lib/checklist.js`) — разные номера одного и
  того же кейса. Связь между ними сегодня частично теряется:
  `ORIGIN_RE` в `lib/inbox.js` уже разбирает `Origin` (`ISSUE-ID#TC-NNN`) и
  захватывает `TC-NNN`-половину, но отдаёт только `issueId`, отбрасывая
  сам `TC-NNN`. Реализация issue должна пронести этот `TC-NNN` до
  `manualTestItemView()` (`public/inbox.js`) → `inboxTargetHash()`/
  `parseRoute()` (`public/app.js`) → `maybeScrollToPtcId()`
  (`public/workspace.js`), которая ищет `[data-tc-id="..."]`.
- Фикстуры для этой части — issue с продуктовым тест-планом, где хотя бы
  одна pending-строка имеет `Origin`, разбираемый `ORIGIN_RE`, и
  соответствующий `manual_test_checklist.md` с тем же `TC-NNN`.

### TC-008: Подсветка и прокрутка реально воспринимаются в браузере

`scrollIntoView` вызван, класс/атрибут подсветки выставлен) уже проверена

же цветом фона, что и остальная страница) и сама сходит через разумное
время.

**Preconditions:**
- Локальный Manual Test UI запущен (`make test-ui` в
  `tools/manual-test-ui/`) на фикстурном или реальном проекте с открытым
  issue, у которого продуктовый тест-план содержит pending-строку с
  разбираемым `Origin`, а чек-лист issue содержит соответствующий
  `TC-NNN`.
- Открыт настоящий браузер (не headless-DOM теста).

**Steps:**

| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | В глобальном инбоксе кликнуть по пункту, относящемуся к этому тест-кейсу. | Экран переходит на нужный проект/issue, вкладка чек-листа открыта. |
| 2 | Наблюдать за экраном сразу после перехода. | Страница плавно прокручивается так, что нужный тест-кейс оказывается в видимой области (не требуется ручной прокрутки, чтобы его найти). |
| 3 | Оценить визуальную подсветку тест-кейса. | Подсветка заметна на глаз (контраст с фоном соседних кейсов), не мешает читать текст кейса. |
| 4 | Подождать несколько секунд. | Подсветка временная — гаснет сама, без перезагрузки страницы. |

**Требуемые данные:** не требуются

**Expected Outcome:** Прокрутка и подсветка не только технически
отрабатывают, но и реально помогают тестировщику увидеть нужный кейс.

**Priority:** Medium

### TC-009: Поиск не персистентный — в отличие от ролевого фильтра

что было введено в прошлый раз. Это осознанное отличие от `.role-switch`
(`ROLE_STORAGE_KEY = "pf.role"`), который персистентен.

**Preconditions:**
- Раннер — `node --test tools/manual-test-ui/test/launcher.test.js`.
- Чистый `localStorage`/фейковое storage-хранилище на входе.

**Steps:**

| Step | Action | Expected Result |
|------|--------|-----------------|
| 1 | Смонтировать лаунчер, ввести непустую подстроку поиска, дать отфильтроваться. | Список отфильтрован по подстроке. |
