## TC-008: Подсветка и прокрутка реально воспринимаются в браузере

**Prerequisites:**
- Подготовленные данные распакованы (см. «Требуемые данные» ниже), и внутри
  подготовленной папки `project/` выполнено:
  `git init -b main && git add -A && git commit -m "fixture"` — это разовая
  подготовка тестовых данных под git, без которой инструмент не увидит issue
  внутри фикстурного проекта.
- Путь к подготовленной папке `project/` добавлен как проект в
  `tools/manual-test-ui/projects.json` (ключ `projects`, поле `path` —
  абсолютный путь к `project/`).
- Инструмент запущен локально (`make test-ui` в `tools/manual-test-ui/`).
- Открыт настоящий браузер (не автоматизированный тест).
- Подготовленные данные: <tmpdir>/pf-test-data/20260818-improve-project-explorer-launcher-search-and-tc-scroll/TC-008

**Требуемые данные:**
- `project/` — фикстурный проект с одним открытым issue (`20260101-feat-fixture-checklist`), у которого есть тест-план проекта с ожидающей строкой и чек-лист с тест-кейсом `TC-001`, на который эта строка ссылается

**Steps:**

| Step | Action | Expected Result | Result |
|------|--------|-----------------|--------|
| 1 | На глобальном экране инбокса (`#/inbox`) найти блок нужного проекта и строку нужного issue в сводной таблице; кликнуть по ссылке issue. | Происходит переход на экран инбокса проекта, автоматически прокрученный к группе этого issue. | [ ] |
| 2 | В группе issue, в разделе «Ручные тесты», кликнуть по пункту, соответствующему тест-кейсу с известным номером. | Экран переходит на проект/issue, открыта вкладка чек-листа. | [ ] |
| 3 | Наблюдать за экраном сразу после перехода. | Нужный тест-кейс оказывается в видимой области экрана без ручной прокрутки. | [ ] |
| 4 | Оценить визуальную подсветку тест-кейса. | Подсветка заметна на глаз (контраст с фоном соседних кейсов), не мешает читать текст кейса. | [ ] |
| 5 | Подождать не более 10 секунд, не выполняя никаких действий. | Подсветка снимается сама — без перезагрузки страницы и без действий пользователя. | [ ] |
