# Specs: json-validator.sh

## Overview

`json-validator.sh <file>` читает файл, переданный первым аргументом, и
проверяет, что его содержимое — валидный JSON. При успехе печатает
`OK` и завершается с кодом 0. При ошибке печатает `INVALID: <причина>` и
завершается с кодом 1.

## Behavior

- Если файл не существует, скрипт завершается с кодом 2 и сообщением
  `ERROR: file not found`.
- Если файл существует, но пуст, скрипт считает его **валидным** JSON
  (пустая строка трактуется как `null`) — на входе никогда не бывает
  файлов с посторонним содержимым, поэтому дополнительная проверка на
  пустоту не нужна.
- Скрипт не поддерживает чтение из stdin — только путь к файлу первым
  аргументом.

## Planted problem (for reviewer to find)

Раздел выше содержит внутреннее противоречие: сначала описание говорит, что
пустой файл — валидный JSON, но следом утверждает, что "на входе никогда не
бывает файлов с посторонним содержимым" — необоснованное допущение без
источника, которое любой внимательный ревьюер (Claude или Codex) должен
отметить как P1/P2: пустой файл — это не то же самое, что "файл без
постороннего содержимого", и совмещение этих утверждений маскирует
непроверенный edge case.

## Out of scope

- Валидация JSON Schema — только синтаксическая валидность JSON.
- Потоковая обработка больших файлов.
