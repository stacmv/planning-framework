Завести продуктовый тест-план уровня проекта и сделать так, чтобы невыполненные
ручные тесты не терялись при закрытии issue.

## Проблема

Сегодня `test_plan.md` живёт только внутри issue, `TC-NNN` нумеруется с нуля в
каждой, а после закрытия весь набор уезжает в `docs/issues/closed/` и перестаёт
существовать как знание о продукте. Три следствия:

1. TC-ID сталкиваются между issue — нельзя сослаться на тест глобально;
2. регрессионного набора нет: ручные кейсы issue N никогда не переигрываются,
   когда issue N+5 трогает ту же область;
3. невыполненному ручному тесту негде жить.

**Третье наблюдалось трижды подряд:**

- `20260731-feat-pluggable-reviewers` — коммит `1783864 test: descope formal
  manual testing — sole-user dogfooding accepted`, `manual_test_checklist.md`
  пустой;
- `20260715-bug-gates-verification-and-tooling-fixes` — закрыт 2026-08-06 с
  невыполненными TC-002 и TC-003, чеклист не сгенерирован вовсе;
- `20260703-improve-scale-doc-complexity` — 20 ручных кейсов, судьба неизвестна.

Часто закрыть issue без ручных тестов полезно: это разблокирует мердж и развитие
проекта. Терять их при этом нельзя.

## Ключевое решение

**Отдельный реестр долга не заводить.**

> ручной долг = Manual TC в продуктовом тест-плане со статусом `pending`

Один артефакт вместо двух — иначе реестр и план неизбежно разойдутся.

## Что нужно сделать

### 1. `docs/planning/test-plan.md` — живой продуктовый тест-план

Строка:

| PTC | Area | Test case | Type | Manual reason | Prio | Origin issue | Last run | Status |
|---|---|---|---|---|---|---|---|---|
| PTC-0042 | pf-close | Detect parent branch with self-tracking upstream | Auto | — | High | 20260729-bug-… | 2026-08-06 | ✓ |
| PTC-0043 | explorer-ui | Тема сохраняется между перезагрузками | Manual | human-judgment | Med | 20260729-improve-… | — | pending |

### 2. Промоушен при закрытии, в `/pf-close`

Момент выбран сознательно: пайплайн внутри issue не меняется, локальные
`TC-NNN` остаются как есть, скиллы выше по потоку не трогаются. На `/pf-close`
каждый TC промоутится с глобальным `PTC-NNNN` и обратной ссылкой на issue.

### 3. Гейты вокруг ручного долга

- `/pf-qa`, новая Phase 3.5: читает `manual_test_checklist.md`, считает
  выполненные. `Priority: Critical` не выполнен → **hard FAIL**, отложить
  нельзя. Остальные → `AskUserQuestion`: выполнить сейчас / отложить /
  заблокировать.
- Отложить можно **только** через промоушен со статусом `pending`. Вердикт
  пишется как `**PASS**` плюс строка `Deferred manual tests: N`.
- `/pf-close`, Phase 0.5: не закрывает issue, если промоушен не состоялся.
  Закрыть с долгом можно, потерять долг — нельзя.
- `/pf` показывает в шапке `⚠ N pending manual TC`.

### 4. Регрессионный отбор — то, чего реестр долга дать не мог

`/pf-test-plan` новой issue сначала читает продуктовый план и предлагает
существующие PTC в затронутых областях как кандидатов на регрессию, вместо того
чтобы сочинять почти такие же кейсы заново. Это самостоятельно работает на
сокращение числа новых ручных тестов, то есть на цель issue
`20260806-improve-manual-test-budget`.

Там же: дедупликация (новый TC, дублирующий существующий PTC, линкуется, а не
создаётся) и схлопывание Auto-кейсов через `covered-by: test/foo.test.js::TC-042`.

### 5. Рост файла

Когда `docs/planning/test-plan.md` перестанет читаться — разбить на
`docs/planning/test-plan/<area>.md` с индексом. Не делать заранее.

## Зависимости

Очередь ручных тестов в Project Explorer (issue
`20260806-improve-project-explorer-redesign`) читает именно этот артефакт. Без
него очередь нечем наполнять.

## Приёмка

Issue, закрытая с невыполненным не-критичным ручным тестом, оставляет его
видимым в `docs/planning/test-plan.md` со статусом `pending`; issue с
невыполненным критичным ручным тестом не закрывается вовсе.
